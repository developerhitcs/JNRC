### Production deployment checklist

Complete and verify these steps before deploying; local XAMPP settings are not production settings.

1. **Database:** Provision the production database and its schema before importing data. Configure `application/config/database.php` with the production host, database name, and a dedicated least-privilege database account. Do not use the local `root` account or a blank password in production. Back up the database before importing data, and do not assume the insert-only sample dump is a schema migration. Review and apply each versioned feature migration once, in order: `database/migrations/202610270001_create_admit_card_release_tables.sql`, then `database/migrations/202610270002_add_admit_card_center_qr.sql`.
2. **Site URL and cookies:** Set `application/config/config.php`'s base URL to the production HTTPS URL, including its trailing slash. The default cookie domain is host-only, avoiding accidental cross-site or localhost cookies; set a shared domain only if cross-subdomain sessions are explicitly required. Secure session, general, and CSRF cookies follow the HTTPS request flag. If HTTPS terminates at a reverse proxy, ensure the application reliably detects the original HTTPS request before relying on this setting.
3. **Assets:** Deploy the complete `assets/` and `assets_admin/` directories at the application web root, preserving their directory structures and filename case. Deploy candidate photos/signatures under `uploads/exam_form/{ref_no}/` using the `img1`/`img2` filenames stored on each exam form, and deploy the approved Registrar signature to `uploads/signatures/registrarsignature.png` if it is required on the PDF. Verify that representative CSS, JavaScript, image, and plugin URLs return HTTP 200 after deployment.
4. **CAPTCHA:** Ensure PHP GD is enabled and both CAPTCHA directories exist and are writable by the web-server account. Load the admin and contact pages and verify each generated CAPTCHA image returns successfully.
5. **Composer/PHP:** Deploy `composer.json` and `composer.lock`, then run `composer install --no-dev --optimize-autoloader` with PHP 7.4 and verify the required extensions (`iconv`, `gd`, and the existing Dompdf/XML requirements). Do not copy the development database settings into production.
6. **Admit cards:** Ensure the existing uploaded photos/signatures are deployed under `uploads/exam_form/{ref_no}/` and that the Apache/PHP account can read them. Verify one Admin release with a selected exam center, an Institution download, QR scan and public verification; then withdraw the release and confirm its prior QR becomes invalid.
7. **Smoke test:** Check the homepage, an inner page, static assets, CAPTCHA display, and login/session behavior using the production HTTPS hostname before announcing the deployment.
