CAPTCHA generation also requires PHP's GD extension and writable output folders for the Apache account.

### Production deployment checklist

Complete and verify these steps before deploying; local XAMPP settings are not production settings.

1. **Database:** Provision the production database and its schema before importing data. Configure `application/config/database.php` with the production host, database name, and a dedicated least-privilege database account. Do not use the local `root` account or a blank password in production. Back up the database before importing data, and do not assume the insert-only sample dump is a schema migration.
2. **Site URL and cookies:** Set `application/config/config.php`'s base URL to the production HTTPS URL, including its trailing slash. The default cookie domain is host-only, avoiding accidental cross-site or localhost cookies; set a shared domain only if cross-subdomain sessions are explicitly required. Secure session, general, and CSRF cookies follow the HTTPS request flag. If HTTPS terminates at a reverse proxy, ensure the application reliably detects the original HTTPS request before relying on this setting.
3. **Assets:** Deploy the complete `assets/` directory at the application web root, preserving its directory structure and filename case. Verify that representative CSS, JavaScript, image, and plugin URLs return HTTP 200 after deployment.
4. **CAPTCHA:** Ensure PHP GD is enabled and both CAPTCHA directories exist and are writable by the web-server account. Load the admin and contact pages and verify each generated CAPTCHA image returns successfully.
5. **Smoke test:** Check the homepage, an inner page, static assets, CAPTCHA display, and login/session behavior using the production HTTPS hostname before announcing the deployment.
